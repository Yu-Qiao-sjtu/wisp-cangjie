# 可编辑 PPT 导出规范

用户要求"可编辑的 PPT 版本"时，从同一份内容清单 JSON 生成原生 PowerPoint 形状的 PPTX。本规范来自一次真实基金技术路线图交付的完整返工记录，逐条都是实测踩过的坑。

## 生成路径

- 优先 `python-pptx` 生成原生形状；**不要依赖 PowerPoint COM 自动化来创建文稿**（COM 新建文稿易失败、易被占用）。COM 可用于最后的实际渲染预览导出。
- 修改 OOXML 时用 `lxml.etree`，不要用标准库 `xml.etree`（python-pptx 的 XML 对象属于 lxml，混用会报错）。东亚字体等属性需写入原始 XML。
- 脚本文件若经 PowerShell 执行，保存为带 BOM 的 UTF-8，否则 Windows PowerShell 5 按系统编码读取，中文字符串会破坏引号解析。
- 每个卡片是独立圆角／直角矩形、每条连线是独立 connector、阶段括号由独立线段组成、文字可单独编辑；**嵌入图片／媒体数必须为 0**，不把 SVG／PNG 整图贴入幻灯片。

## 字体与版式（默认值，用户或模板另有规定时从其规定）

- **中文宋体（SimSun）、西文／数字 Times New Roman，全部统一 10 号**。同一文本框内的双字体规则写入 `a:ea`＝SimSun、`a:latin`／`a:cs`＝Times New Roman，中英文自动各用对应字体。
- 不依赖 PowerPoint 主题字体（换机器不失真）；逐 run 核对字号。
- **段落用单倍行距**（`line_spacing=None` 即默认单倍），上下内边距约 0.10–0.13cm，左右约 0.08cm。人为压到 0.85 倍行距会显得拥挤，用户一定会要求改回。
- **关闭全部主题阴影**：python-pptx 会给每个形状写入主题 `effectRef idx="2"`，PowerPoint 将其渲染为阴影。保存后清除所有形状的主题效果引用，并核验阴影引用数为 0。
- 页面比例与路线图一致，单页纵向。

## 页面尺寸规则（实测重大返工）

- 页面尺寸**对齐用户的模板或目标文档**（常见基金模板为 19.05 × 27.51cm 纵向 A4 比例）。
- 内容放不下时，**通过精简语言适配页面**：合并相近实验、减少阶段性重复结论框、每框压缩为"动作＋核心读出"短句；细节保留在正文。绝不允许拉长页面（26 × 51cm 的长页会被直接退回），也不允许把字号降到约定值以下。

## 模板学习协议

用户提供 `.pptx` 模板时：

1. **先备份**当前要改造的文件（archive 子目录＋时间戳后缀），新版本另存新文件名，绝不覆盖模板和现有交付物。
2. 结构化解析模板：页面尺寸、每元素的坐标／层级／填充／边框／字体／字号／对齐、箭头样式、分组结构，并导出模板的实际渲染预览（不要只从 XML 推测风格）。
3. 提取**视觉语法与语言风格**（如：白底、直角矩形、细黑边框、无阴影；浅粉仅用于前期发现与阶段结论；白底普通任务框；浅蓝仅强调关键实验；黑色虚线表候选分支；左侧纵向阶段名＋单侧括号；"动词＋对象"短句），**不机械复制**模板的节点数量、位置、具体内容、长回流箭头或页面尺寸（页面尺寸仍按上面的页面尺寸规则决定取舍）。
4. 迁移后保留我们的拓扑与科学内容；写一份模板风格审计说明供用户核对。

## 验收（与 SVG 同样强制，另有 PPT 专属项）

- 结构核验：原生形状数、连线数、嵌入媒体＝0、必备节点标题缺失＝0、ZIP／OOXML 完整性。
- **文字越框检测循环**：用 PowerPoint 实际文字边界（`TextRange2.BoundWidth`／`BoundHeight`，减去内边距得可用区域）逐框检测，输出检测表；通过增高卡片、同步移动箭头端点、精简措辞、为超长英文单词加宽 0.1–0.2cm 消除溢出，**不缩字号**。循环到溢出数＝0 才可交付（实测首轮可达 14–27 个溢出，需多轮）。
- **PowerPoint 实际渲染验收**：用本机 PowerPoint 打开并导出整页预览，逐项检查字号、换行、阶段标题是否被压成逐字竖排、阴影、图例与他框重叠、文字越框。XML 层面合格不等于渲染合格，初版常见 5 类渲染问题（字号偏大、强制换行、竖排事故、主题阴影、图例重叠）。
- COM 注意事项：PowerPoint 忙时导出会被拒（`RPC_E_CALL_REJECTED`），只关闭自动化留下的空白实例，不干扰用户正打开的文档；预览导出可能超过工具超时，用长任务执行并检查是否已在后台完成，不要反复重建文件。

## 归档规则

重大重构或风格迁移前，把现有交付物复制到 `archive/`（带时间戳后缀）再生成新文件；每次交付说明中列明全部历史版本与模板的路径。用户提出修改时优先增量修改当前版本；用户明确指出结构框架错误时先归档再重排。
