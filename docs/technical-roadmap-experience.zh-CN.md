# 技术路线图绘制经验沉淀（research-roadmap）

> 场景：绘制**论文、研究报告（开题／进展／结题）、基金申请书**的整体技术路线图。
> 可执行载体：bundled skill（本仓库 `skills/research-roadmap/`，安装于用户
> `~/.wisp/skills/`）。本文是该 skill 背后的经验总结，记录一次真实基金技术
> 路线图交付中十余轮人工返工暴露的问题，以及它们如何被固化为规则与自动检查。
> 调研与沉淀日期：2026-09-15。

## 一、交付形态

| 产物 | 说明 |
| --- | --- |
| SVG 源文件 | 原生文本／形状／折线，中文可编辑，默认交付 |
| PNG 预览 | 实际渲染，含目标插入宽度（默认假设约 16 cm）预览与密集区局部裁图 |
| 可编辑 PPT | 按需交付；原生 PowerPoint 形状，嵌入位图为 0 |
| draw.io | 按需交付；原生顶点与连线，非嵌图 |
| 内部 JSON | 节点／边／坐标的单一维护源，SVG／PPT／draw.io 均由它生成，默认不交付 |

## 二、一次真实返工记录 → 固化对照表

以下问题全部来自一次真实基金（PTK7–YAP/TEAD 方向）技术路线图的人机协作交付；
左列是用户实际提出的返工意见，右列是沉淀位置。

| 用户返工意见（原话摘要） | 根因 | 已固化为 |
| --- | --- | --- |
| "线条歪歪曲曲" | 多段路由含斜向段，检查器原本只查"穿框" | `check_graph.py`：多段路由斜向段＝ERROR |
| "本来该是竖线，它却拐弯" | 主轴节点偏移 15–30px，用折角补偿 | 布线规则：主轴节点共享中线；`check_graph.py`：间距≤90px 拐弯＝WARN |
| "间距过小就直接直线，不要拐弯" | 汇聚处滥用总线，26 条短距连线带 2–4 个拐点 | 布线硬规则：相邻卡片边界直连（允许短斜线，禁小折角） |
| "看一下示范图的框架……顺序可能不一样" | 按申请书章节标题分层，而正确组织是证据形成阶段、按实验依赖排序 | 参考图协议：提取组织框架／视觉语法／语言风格三层 |
| "方框语言是动词+名词词组？科学假说没必要说'提出科学假说'" | 目录式标题＋元话语 | 文案规则：动词短语；禁"提出核心科学假说／形成预期研究结论" |
| "方框内行距是单倍吗？" | 人为压成 0.85 倍行距 | PPT 规范：单倍行距，内边距 0.10–0.13cm |
| "为什么有那么多阴影？中文宋体10号，英文 Times New Roman 10号" | python-pptx 主题 `effectRef idx=2` 自动加阴影；字号各自为政 | PPT 规范：清除主题效果，双字体统一 10 号，逐 run 核对 |
| "demo 是标准 A4，你怎么那么长？" | 靠拉长页面（26×51cm）容纳内容 | 页面尺寸规则：对齐模板；放不下精简语言，不拉页面不缩字号 |
| "字体有的超越边框，你需要自己识别调整" | 凭肉眼判断溢出 | PPT 规范：`TextRange2.BoundWidth/Height` 逐框检测循环至溢出＝0（实测首轮 14–27 个） |
| "整体动物实验应该独立成阶段" | 阶段划分不完整，动物实验被压进递送模块 | 组织框架规则：每个有独立结论输出的研究层次都是独立阶段 |

## 三、工作流（五步）

1. **三问确认门**：首次输出方案前，一次性确认①有无参考图②纳入哪些章节③整图还是分图。
   未答复的提问不构成许可；"请帮我画技术路线图"本身不跳过此门。
2. **内容清单**：稳定节点 ID＋简明标签＋原文出处＋语义类型；边记录起点、终点、
   关系类型和依据。区分流程依赖（实线箭头）、方法支撑（旁注）、组织装饰（分组框）。
   待验证假说不得写成确定结果。
3. **拓扑确认**：文本草图确认节点、分组与连接逻辑；Mermaid 不作最终渲染器。
   确认后排版可变，内容不可变。
4. **排版生成**：JSON 与 SVG 同源生成；按布线硬规则走线；阶段标题占独立左栏。
5. **硬验收门**：检查器 0 errors 且 0 布线 WARN，加实际渲染的整图＋局部人工检查，
   缺一不可交付。格式检查、视觉检查、科学正确性三者互相独立。

## 四、布线硬规则（最高频返工来源）

- **相邻卡片直连**：边界间距小（约 ≤90px）时一条线从边界到边界；中心对齐即竖线，
  轻微错位允许一条短斜直线；禁止为汇聚加两段以上小折角。
- **多段路由仅用于分叉**：一对多／多对一、跨阶段、绕行时才用"水平总线＋垂直落线"，
  每段严格水平或垂直。
- **主轴共享中线**：上下主轴节点对齐同一横坐标，连接为单一竖线。
- **移动即复检**：每次移动节点后重跑检查器，清除旧坐标残留。
- **密集区并行证据链**：发现较多的模块（如前期研究）拆成生物学链与药物链等并行链，
  各链先汇入本链结论框、再纯竖线进入下一层；禁长回折线；汇聚方式对称。
- **侧栏独立**：阶段标题与括号不侵入卡片横向范围，括号间留间隔不重叠。

## 五、组织框架与文案

- 路线图按**证据形成阶段**组织，不按文档章节标题竖排。典型原型：前期研究发现 →
  细胞功能分析 → 分子机制鉴定 → 治疗策略构建 → 整体动物实验 → 治疗评价
  （名称随项目变化）；**顺序由实验依赖决定**（谁为谁提供材料或结论），不是固定模板。
- 方框文案用动词＋名词词组（鉴定…影响、考察…调控、阐明…机制、评价…效能）；
  禁目录式标题；禁元话语。一框一至两行"动作＋核心读出"；试剂浓度、给药频率、
  载体序列等细节留在正文。

## 六、可编辑 PPT 交付要点

- 生成：`python-pptx` ＋ `lxml`（COM 创建文稿不稳）；脚本存 UTF-8 BOM（PowerShell 5 编码坑）。
- 版式：中文宋体／西文 Times New Roman 双字体（`a:ea`／`a:latin`／`a:cs`）统一 10 号；
  单倍行距；清除全部主题阴影（`effectRef`）；页面尺寸对齐模板，内容放不下精简语言。
- 验收：PowerPoint 实际渲染预览 ＋ `TextRange2.BoundWidth/Height` 逐框越框检测循环至 0；
  XML 层面合格不等于渲染合格。
- 模板学习：先备份，解析模板的视觉语法与语言风格后迁移；不复制布局、节点数、内容；
  不强行套用模板页面尺寸。重大重构一律 archive/ 时间戳归档，绝不覆盖历史版本。

## 七、可复用的检查器

`skills/research-roadmap/scripts/check_graph.py`（纯标准库）覆盖：画布与几何合法性、
节点重叠、ID 一致性、连线穿越无关节点、端点贴边警告、**多段路由斜向段（ERROR）**、
**短间距拐弯（WARN）**。任何层次化流程图／路线图类交付都可以直接复用或扩展它；
"格式校验＋渲染目检"双门缺一不可。
