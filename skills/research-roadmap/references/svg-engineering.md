# SVG 排版和工程规范

## 从内容清单到坐标

1. 确定目标尺寸和布局，给阶段／模块分配区域。
2. 选择实际存在的中文字体。中文建议 Noto Sans CJK SC、Source Han Sans SC、PingFang SC、Microsoft YaHei；需要宋体风格时选择实际安装的相应字体。Arial 仅用于西文回退，不当作中文字体保证。
3. 用可用浏览器的 Canvas `measureText` 或 Pillow 配合真实字体测量文字；确定换行后计算框高。字符数只能用于初排，不能作为不溢出的证明。
4. 同类节点采用少量统一宽度；框高由行数、行距和内边距决定。文字长时先语义精简／增高，再考虑改宽，避免逐框缩小字号。
5. 行内间距建议至少为正文一个字高，模块间距约为其两倍；按实际画幅调整。为连线与旁注预留通道。

## 形状与文字

采用原生 `rect`、`ellipse`、`path`、`polyline`、`text`／`tspan`。文字正确转义 XML 特殊字符，禁止用 foreignObject 放置核心文字，以提高跨软件兼容性。保留中文可编辑文本，不默认转曲。

为任务外层 `g` 设置 `id="节点ID" data-node-id="节点ID"`。每条语义连接使用 `id="连接ID" data-edge-id="连接ID"`，并记录 `data-source`、`data-target` 和 `data-kind`。JSON 中的边界框是实际任务形状的包围盒，不把装饰标题算为任务。

推荐绘制顺序：背景、模块底色与边界、连线、任务形状、文字、旁注。避免后绘制的分组边框穿过节点。白底，深灰线条；按角色定义统一颜色与线宽。不要默认给每个节点加阴影。

## 连接与汇聚

连接起终点置于实际形状边界；矩形可用边中点，椭圆等按几何边界求交。marker 的尖端与 refX 对齐，明确 markerUnits，避免改变线宽造成巨大箭头。方向与节点端口按关系和布局选择，不强制所有侧向线都连中点。

### 布线硬规则（实测返工教训）

- **相邻卡片直连**：两个卡片边界间距小（约 ≤90px）时，从上框边界直接连到下框边界，一条线完成。中心对齐时是竖线／水平线；轻微错位时允许一条短斜直线。**禁止为汇聚而加两段以上的小折角**——"本该竖线却拐弯"是用户最频繁的返工原因。
- **多段路由仅用于分叉**：只有一对多／多对一汇聚、跨阶段连接或需要绕开卡片时才使用"水平总线＋垂直落线"，且每一段必须严格水平或垂直（正交），不允许斜向段。
- **主轴节点共享中线**：上下主轴节点统一对齐到同一横坐标（如画布中心），保证主轴连接是一条单一竖线，不靠折角补偿 15–30 像素的偏移。
- **节点移动后必须清理旧坐标**：每次移动节点后重跑检查器；移动遗留的旧坐标是斜线和错位端点的主要来源。
- **密集发现区用并行证据链**：发现较多的模块拆成两条以上并行链（如生物学证据链与药物证据链），各自先汇入本链结论框、再用纯竖线进入下一层；禁止把多个来源不对称地直接折进同一节点，也禁止长回折线绕到目标侧边。
- **汇入方式对称**：多个框共同汇入同一结论时，用统一的"竖直落入"或统一的"总线汇入"，不混用不对称短折线。

折线在 JSON 中保留完整 points。`scripts/check_graph.py` 会把"多段路由含斜向段"记为 ERROR、"间距 ≤90px 却拐弯"记为 WARN；交付前两者都必须清零。交叉尽量通过调换节点顺序或走外部通道解决；共享汇聚干线允许重合，但不能暗示不存在的样本混合或因果关系。只有真正的连接才画连接点；无关交叉应绕开或明确区分。

## 渲染与可读性

优先使用实际环境已有的浏览器 SVG 渲染；也可使用支持当前 SVG 和字体的 CairoSVG、resvg 或系统预览工具。先检查可用性，不能假定所有平台已装工具。无需为了此技能安装 TikZ 或调用图像生成模型。

如需新增轻量渲染依赖，按运行环境的权限规则处理；无法渲染时仍交付 SVG，但明确标为“未完成视觉验收”，不要伪称已查看图片。渲染器不能解析所选字体时，先解决字体或换可用字体再检查。

PNG 用于查看与文档插入，建议按目标物理尺寸输出约 300 dpi。单独检查实际插入宽度下的阅读效果，不能只看高倍率预览。缩略预览关注主线和模块，局部关注文字、箭头、边框与空隙。

## 检查边界

`scripts/check_graph.py` 检查 JSON 与 SVG 的任务／连接 ID、边引用、画布范围、节点包围盒重叠、连线穿越无关节点及几何端点警告。它不测量真实字形、不证明 SVG 图形坐标与 JSON 完全一致、不理解科学语义，也不识别所有曲线及线线相交。必须结合渲染与人工对照。

## draw.io 按需输出

同一 JSON 可映射到 mxGraphModel：节点生成 vertex，关系生成 edge，标签转义并保留换行；x/y/width/height 写入 mxGeometry，折线控制点写入 points。source/target 引用对应节点 ID。旁注和分组也需使用可编辑元素，不把整张 SVG 包成 image。SVG 文本对象可编辑与 draw.io 原生节点可编辑是两种不同承诺，交付时说清楚。
