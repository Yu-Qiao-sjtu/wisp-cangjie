# RIA-TV++ 方法论总览

本文是本 skill 所用 SOP 的设计说明,解释"为什么这么做"。执行时的具体步骤请读 `SKILL.md` 与 `references/methodology/` 下 01 至 08 各阶段文档(含阶段 0.5 的 01b、阶段 1.6 的 03b)。

## 命名

**RIA-TV++** =
- **RIA** — 赵周 (《这样读书就够了》) 的便签拆书法: Reading / Interpretation / Appropriation
- **TV** — Triple Verification,三重验证
- **++** — 面向 agent 执行的扩展: E (Execution 可执行步骤) + B (Boundary 边界)

## 思想来源

| 来源 | 借鉴内容 |
|---|---|
| Mortimer Adler 《如何阅读一本书》 | 阶段 0: 分析阅读三阶段 (结构/解释/批判) |
| 赵周 RIA 拆书法 | 阶段 2: R-I-A1-A2 基本骨架, 尤其 A2 → trigger |
| Niklas Luhmann Zettelkasten | 原子化 + 链接 + 用自己的话重写 |
| Tiago Forte Progressive Summarization | 阶段 4 的"可验证压缩链条"思想 |

## 根本洞察

**现有读书方法论都是为人类读者蒸馏,不是为 agent 执行者蒸馏。**

| 维度 | 给人看 | 给 agent 用 (本 skill 目标) |
|---|---|---|
| 关键字段 | 故事 / 金句 / 情感钩子 | trigger / 可执行步骤 / 判停标准 |
| 失败模式 | 读完就忘 | trigger 不准 → 永不调用或乱调用 |
| 成功标准 | 读者"有收获" | 真实问题被解决 |

所以 RIA-TV++ 的所有"扩展"(TV / E / B / test-prompts) 都是为了解决这个目标迁移带来的新问题。

## 源类型路由 (v2.3)

流水线对两类源材料开放,骨架相同、差异层不同:

- **书籍模式(默认)**: 书籍、长视频转写、播客、课程、访谈、长文、资料集 — 01–07 各阶段文档;
- **论文模式**: 期刊/会议论文、预印本(含补充材料,可附带代码库/数据集) — 在 01–07 之上叠加 `08-paper-mode.md` 的差异层(论文结构理解、第 6 个可复现性提取器、可验证性分级、引用规范)。

模式判定在 Inputs 阶段由用户确认,不确定时不猜。两模式产物形态(single/pack)、硬门通用条款与评测体系完全一致。

## 不变量 (任何迭代都不能违反)

1. **原子性**: 一个能力只做一个方法论单元,不能"大而全"（single 的"一个"指一个发现入口,内部能力仍原子化）
2. **可追溯**: 每个能力必须有原文引用,指向源书章节 (视频指向时间戳/分 P)
3. **可验证**: 每个能力必须通过三重验证 + 压力测试
4. **可进化**: 每个晋级 Skill 必须附带可复跑的评测用例 (test-prompts.json)
5. **用户参与**: 阶段 0 之后必须让用户确认骨架; 阶段 1.5 之后必须让用户确认入选名单; 阶段 5 编译前必须让用户轻确认输出模式
6. **可交付**: 流程终点是"用户能调用"— 编译产物必须被安装到 skills 目录,读者需求由 DIGEST.md 承接
7. **单一事实源** (v2.1): single 与 pack 从同一份 Capability Bundle 编译,引用同一组稳定 capability_id;生成目录只读,检测到本地手改不得静默覆盖
8. **能力不失联** (v2.1): 未晋级能力保留为来源路由入口内的能力卡,每个 active 能力在 destinations 中恰好一个去向
9. **覆盖不自证**: 原书关键任务清单独立于旧版通过候选；重要机制即使只出现一次，也要有候选与明确去向
10. **语义留痕** (v2.4): 理解不止步于摘要 — 阶段 0.5 语义母本把主张/证据/推理/假设/边界固化为全锚点工件;下游压缩从母本发生,不从格式发生
