# 阶段 4b — 语义保真测试（理解留痕的验证端）

## 目标

验证端只验"来源充分性"不够——**卡片是否忠实传递了逻辑链**必须单独验证。信息丢失可以在"每张卡单独看都没问题"的情况下发生（issue #15）。

本阶段与 V1–V3 并行：V1–V3 验「来源充分 / 可执行 / 任务增益」，本阶段验「**理解保真**」——主张 → 证据 → 推理 → 边界 的逻辑链在压缩进卡片后是否仍可重建。不通过 → 回炉**阶段 2**（以母本节点簇重编译 I/E/B），不是改卡面文字。

前置依赖：语义母本存在（阶段 0.5，见 `01b-stage0.5-semantic-map.md`）时用完整协议；无母本的项目走**降级协议**（源文级「应载论点清单」对照，见 L1 末），不做伪对照（拿卡自身当基准不算保真测试）。

## 三把锁

### L1 — 逻辑链重建测试（结构测试）

**协议**：

1. 从能力卡（或编译产物中该能力的编译节）抽卡，对每张卡启动独立 sub-agent（干净上下文；可用一次盲测跑多张卡，但输入不得互相混淆）；
2. **只给**：卡片全文、任务说明——「仅凭这份材料，重建这套方法成立的『主张→证据→推理→边界』逻辑链，逐环节标注材料内出处；材料中没有的环节标『材料未含』」；
3. **不给**：源文、语义母本、原书任务清单、预期答案、本测试的判卷标准；
4. sub-agent 输出：节点化链（claim / evidence / reasoning / assumption / boundary，字段同构 semantic-map：statement + 材料内出处）+ 自评缺口清单；
5. 主流程判卷：重建链与语义母本**逐节点对照**，填判卷表（每节点一行，留档）；判定「断裂」前必须**回卡复核**——母本节点在重建链无对应**且卡内亦无载体**才是真断裂；卡内有载体而重建缺＝**重建噪声**（骨架重建的粒度局限），不计卡的问题，逐条记录并计入测试局限；
6. run_ref 登记与独立性核对：按 `06-stage4-pressure-test.md` 的独立性登记执行（重建者 run_ref 不得出现在该来源的蒸馏/提取 run_ref 集中）。

**判卷范围固定**：测试前，主流程按卡的任务声明与内容涉及范围，从母本圈定该卡的**责任节点集**（逐节点注明圈定理由），写进判卷表；圈定后不得因测试结果修改（防放水），圈定偏差记入测试局限。

**测试分辨率（如实声明）**：本协议重建任务的分辨率在**骨架层**（为什么成立、何时不成立）；「执行约束 / 输入契约 / 输出格式明细」类内容不在此口径内——它们会在重建中表现为「噪声」（卡内有载体、重建未显形），判卷时按回卡复核处理；需专测时按 L1 末「操作契约面专测（可选口径）」执行。

**降级协议（无母本时）**：从**源文**圈定该能力的「应载论点清单」（5–8 条/卡，逐条标注源文位置，测试前固定；清单不得取自卡片自身），盲测任务与三把锁结构不变，对照物改为清单：论点级同用四级判定 ＋ 回卡复核；报告须标注「降级协议，待母本补齐后升级为完整协议」。用例与判卷表见 `books/ai-topic-validation/evals/rebuild/`。

**判卷标准（节点级，四级）**：

| 判定 | 含义 | 对照口径 |
|---|---|---|
| 通过 | 重建链有对应节点且语义一致（可比母本更粗但不错） | — |
| 断裂 | 母本节点在重建链中无对应 | 卡丢失了该环节 |
| 错位 | 有对应但语义位置偏移（如 boundary 被当成 claim、限定关系被反转） | 卡传递了错误的逻辑位置 |
| 降级 | 有对应但粒度粗化到不可执行（具体判停条件被泛化为笼统原则；explicit 证据被虚化为"有研究表明"） | 触发与判停约束丢失 |

**判定等级（整卡）**：

- **通过**：责任节点集中 claim / reasoning / assumption / boundary 零断裂零错位；evidence 断裂 ≤1 且降级项逐条记录；
- **不通过**：出现 claim / reasoning / boundary 断裂或错位，或降级导致关键判停点失效；
- 不通过 → 回炉阶段 2（重编译该卡的 I/E/B），按失败清单重测；回炉预算沿用 2 轮上限，轮次与结论写回 pipeline 状态；
- 2 轮后仍不通过：按 06 的规则降级（router / reference）并记录，不带病晋级。

**操作契约面专测（可选口径）**：骨架重建对"执行约束 / 输入契约 / 输出格式明细"不敏感（见测试分辨率）；需专测时对目标卡加跑一轮**契约重建**——盲测者仅凭卡片重建三类清单：① 输入契约（必需材料 / 前置状态）；② 执行约束（必须做什么 / 禁止什么）；③ 输出格式明细（输出必须包含什么），逐条标注卡内出处。对照物为测试前从**源文**圈定的契约点清单（逐条注明源文位置，不得取自卡片——防自证），四级判定与回卡复核同 L1。骨架与契约两轮均过方可声明"理解保真"完整成立；仅骨架过则标注「契约面未测」。

### L2 — 回述测试（理解测试）

- 未读过源文的独立 sub-agent 读卡后回答两个问题：「这套方法为什么成立？」「它在什么条件下不成立？」；
- 判据：复述的"为什么"与母本 reasoning 节点语义一致；"边界"与 boundary 节点一致；**不得出现母本没有的因果断言**（脑补检测：新增因果都要能回卡片出处）；
- 与现有 I 段自检（"没读过原书的人能否理解"）衔接：自检升级为有判卷记录的回述测试；
- 可与 L1 合并为一次盲测（先做重建任务、再做开放式回述），但两段分别判卷。

### L3 — 锚点全覆盖机械检查（脚本）

```sh
python scripts/check_semantic_fidelity.py <semantic-map.md> \
    --source <源文文件> --candidates <候选目录> --verified <verified.md>
```

- **层 A 母本结构**（按 `assets/schemas/semantic-map.schema.json`）：字段 / 枚举 / links 目标存在 / 每节点有 location / explicit 引文非空且 ≤150 字 / claim 关联 ≥1 evidence 或显式 missing；
- **层 B 锚点可回查**：引文归一化后回查源文（拼接引用按分隔符分段核验，报告 n/m 段命中）；
- **层 C 候选挂链**：带 `chain_refs` 的候选引用必须指向存在节点；`decision=verified` 的候选必须挂回母本 ≥1 节点（v2.4 链位置核查的机械部分）。
- 退出码：0 = 无 ERROR；1 = 存在 ERROR；2 = 输入无效。**运行时机**：阶段 1.5 产出后跑一次（含 `--candidates --verified`）；进入阶段 5 前再跑一次（屏障检查）；
- 历史项目回填：对无 `chain_refs` 的旧产物，脚本输出的缺链清单即整改清单——补链后重跑，或按 `03-stage1.5` 规则转 `needs_review`；
- 非严格 YAML 的历史记录：脚本按宽容规则抢救解析并记 WARN；新产物应直接写严格 YAML（值内含冒号时加引号）。

## 独立性登记

复用 06 的 run_ref 机制：主流程为每个重建/回述 sub-agent 分配 `run_ref`（角色名 `fidelity-rebuild`），随任务包下发、产出首行回显，登记到 `PIPELINE_STATE.md`「参与者登记」；`test-results.md` 写 `## 保真测试` 小节：`blind_run_refs`、`distiller_run_refs`、`independence_check: pass/fail`、`fallback: true/false`。

**fallback 规则**（无 sub-agent 能力时）：主流程自测时启用**出处硬约束降级**——重建链每环节必须标注材料内出处，出处真实性用 `scripts/check_rebuild_quotes.py <盲测输出> --material <卡片>` 机械回查（归一化后逐条核查，报告 n/m 命中；独立盲测时同样执行，用于验证「逐字出处」声明可信）；记忆污染仍不可完全排除，必须标 `fallback: true` 并声明「独立性未达，置信度受限」。

## 用例沉淀

- 重建测试用例（卡片材料快照引用 + 责任节点集 + 判卷表）沉淀为**回归资产**：存 `evals/rebuild/`，每个用例含 `case_id`、卡片与母本快照引用、上次判卷结果；降级协议用例同目录沉淀（以「应载论点清单」代责任节点集，注明源文位置）；
- 失败用例与回炉历史进回归集（沿用 06 的回炉记录纪律），防质量回退；
- 同一来源的保真测试可整合进 output_cases 的运行报告，但判卷表必须独立留档。

## 母本缺口回扫（反向缺口的闭环）

测试可能发现「源文 / 卡有、母本未登」的反向缺口——这是基准（母本）不完整，不是卡的问题。**测试中不得直接改母本**（防基准放水）；缺口逐条登记（发现 / 源文·卡状态 / 修订建议），走独立回扫流程：

1. 逐条回源文定位锚点（quote ≤150 字、可机械回查；无源文依据的卡侧增强不收编，在缺口清单备注）；
2. 修订母本：新增节点按类型编号（c / e / r / a / b + 序号），status = explicit / inferred / missing 如实标注，inferred 必须给出推断依据；
3. 重跑 L3（`check_semantic_fidelity.py`）验证新引文命中与结构合规；
4. **升级用例**：新节点并入责任集扩展圈定，附「回扫升级记录」（对标复核或复测结果）；原判卷快照不改，升级后基准保留进回归集；
5. 回扫轮次与结论写回测试报告。

试点首轮执行记录见 `books/ai-topic-validation/evals/rebuild/erd-case.md`（回扫升级记录）。

## 与既有机制的关系

- **不替代** V1–V3 与触发/输出评测：这是"理解保真"维度，与「来源充分 / 可执行 / 任务增益」并行；
- 断裂清单直接映射回炉范围（该卡 I 段涉及哪些母本节点）；
- 与 coverage-audit 两级台账衔接：母本节点落位状态可交叉验证（"未落位"节点是断裂的天然候选）；
- 实测结果（试点回填）见 `books/ai-topic-validation/evals/reports/fidelity-rebuild.md`。

## 常见失败模式（防测试走过场）

1. **重建者看过母本** → 独立性失效：run_ref 核对 + 判卷时核对重建链出处是否均来自材料；
2. **重建链脑补**（材料没有的环节被补全）→ "材料未含"标注纪律；判卷反向检查无出处环节；
3. **用一次盲测概括全部结论** → 关键卡至少 1 次独立重建，判卷表逐节点留档；
4. **拿触发测试成绩当保真结论** → 维度不同：触发说"找得到"，保真说"没传丢"；
5. **责任节点集事后调整** → 圈定必须在测试前完成并注明理由（降级协议的「应载论点清单」同理）；
6. **把重建噪声误判为断裂** → 判卷前必须回卡复核（卡内有载体而重建缺＝噪声）；未经复核的断裂清单不得进入回炉范围。
7. **回扫与测试混轮** → 反向缺口修订必须独立于测试轮（先登记、后回扫、再升级用例）；禁止用回扫事后调整责任集掩盖断裂。
