# 阶段 0.5 — 语义母本（逻辑抽取）

## 目标

在整书理解（阶段 0）与并行提取（阶段 1）之间，把"理解"固化为可回查的工件：**主张 → 证据 → 推理 → 假设 → 边界** 的逻辑链，每个节点带源锚点。

没有这一层，提取器只能按各自的格式模板取材，每过一道工序做一次"格式投影"，上游资料越好在产物里越显简略。有了这一层，压缩从母本发生而不是从格式发生：**母本保真，卡片保触发**。

产出：`books/<slug>/semantic-map.md`（模板 `references/templates/SEMANTIC_MAP.md.template`；内嵌 YAML 结构定义见 `assets/schemas/semantic-map.schema.json`）。

母本**不受"必须精炼"的约束**——它不是喂给下游的摘要，而是记录理解的母本；一次生成、全程复用（阶段 1 取材、阶段 1.5 核对、阶段 2 编译、阶段 4 保真对照）。阶段 0 的 `BOOK_OVERVIEW.md` 保持精炼不变（它要喂给每个 sub-agent），母本是独立文件。

## 设计依据

- **Toulmin 论证模型**（The Uses of Argument, 1958）：主张 / 数据 / 担保 / 支援 / 限定 / 反驳，对应本阶段的 claim / evidence / reasoning（含 assumption）/ boundary；现有能力卡的 B 段（边界）即 Rebuttal，本阶段把它从"卡片的一段"提升为"全文级结构"。
- **情境模型理论**（van Dijk & Kintsch, 1983）：阅读理解的本质是构建情境模型（因果 / 意图 / 指称结构），不是保存文本表面——"人先理解语义、再抽取逻辑"的认知科学依据。
- **CLAIM-BENCH（2025）**：LLM 对科学文本的主张-证据逻辑关联存在显著局限；多遍通过、逐一提示可显著改善——本阶段据此采用三遍抽取 + 回扫。
- 生态对标与空白位结论见仓库 issue #13；本阶段落的工程位是"文字 → 语义理解 → 逻辑抽取 → 可执行 skill"链路中缺失的中间环（issue #14）。

## 节点类型（与提取器职责的边界）

| 节点 | 含义 | 与提取器的边界 |
|---|---|---|
| claim | 作者主张的结论性命题 | 不等于框架 / 原则本身；主张是"为什么值得做成 skill"的依据 |
| evidence | 支撑主张的数据 / 实验 / 引文 / 案例 | 案例细节由 case-extractor 提取；母本只登记"哪类证据、在哪" |
| reasoning | 证据为何能支撑主张的推理（warrant）与前提链 | 是卡片 E 段（执行步骤）的推导来源 |
| assumption | 未言明但成立的前提（含适用条件限定） | 推断的必须标 inferred，不许脑补 |
| boundary | 适用条件、反例、失败模式、反驳条件 | 直接喂给卡片 B 段，与阶段 0 批判步互相核对 |

## 三遍抽取（+ 一次回扫）

1. **第一遍 — 骨架**: 通读全文，列出主张清单（c01, c02, ...），与 BOOK_OVERVIEW 的 3–7 条一级论点对齐；每条主张必须能一句话说清。
2. **第二遍 — 证据配对**: 为每条主张找证据节点（e01, ...）；证据类型（实验 / 数据 / 引文 / 案例）与位置必须可回查；原文明确的标 `explicit`，可合理推断的标 `inferred`，找不到的标 `missing`——**不虚报零缺口**。
3. **第三遍 — 推理与边界**: 为"证据 → 主张"补 reasoning 节点；从阶段 0 批判步引入 assumption 与 boundary 节点（作者局限 / 未证明假设 / 最强反对）。
4. **回扫（部分 ↔ 整体）**: 新节点是否修正了骨架？若有，回改第一遍的主张清单——诠释学循环，单遍加工必然有损。

**论文模式差异**（叠加，见 `08-paper-mode.md`）：证据节点锚定到图表编号；节点带版本锚点（DOI / arXiv ID + 版本）防版本漂移；额外记录"贡献 → 任务"映射，与阶段 0 的可复现资源清单互联。

## 节点最小字段（内嵌 YAML）

```yaml
schema_version: 1
source_id: src-main-book
mode: book            # book / paper
nodes:
  - id: c01
    type: claim
    statement: 意外结果的分析应先拆因果链、找断裂点，而非急于否定假说
    status: explicit
    source_anchor:
      location: 第 5 集 第三步
      quote: "对每个环节标注有数据支持、有数据反对或缺乏数据；找出链条断裂的位置"
    links:
      - { to: e01, relation: supports }
      - { to: r01, relation: derives }
    task_ids: [task-09]
```

（合成示例，不是原书引文。）

## 质量门（进入阶段 1 之前必须满足）

- [ ] 每条 claim 至少关联一条 evidence，或显式标 `missing` 并说明缺口；
- [ ] 每个节点有 source_anchor（location 必填；`explicit` 节点 quote ≤150 字 / 英文 ≤100 词）；
- [ ] 阶段 0 的关键任务清单每条能映射到 ≥1 节点（task_ids），未映射的记缺口；
- [ ] assumption 与 boundary 已从阶段 0 批判步过一遍，无证据时标待核查、不编造；
- [ ] 已与 BOOK_OVERVIEW 骨架核对（主张清单不矛盾），并向用户展示确认（可并入阶段 0 的既有确认动作，一次展示两份）。

- **阶段 1**: 每个 extractor 的输入 = BOOK_OVERVIEW + semantic-map + 源文（块）；候选新增 `chain_refs`（挂回母本节点），不挂链的候选不得标 verified；

- **阶段 4**: 逻辑链重建测试以母本为对照基准（v2.5 已接线：协议与判卷标准见 `06b-stage4-semantic-fidelity.md`，机械检查见 `scripts/check_semantic_fidelity.py`）；
- **回扫维护（v2.6）**: 保真测试发现的反向缺口走 `06b` 的「母本缺口回扫」流程修订母本（测试中不改基准）；修订后升级用例、保留回归集。

## 常见失败模式

1. **母本写成摘要** — 它是图（节点 + 关系 + 锚点），不是散文；节点之间没有关系、每条孤立，等于没抽逻辑。
2. **只有 claim 没有 reasoning** — 逻辑链断在"为什么"；这是最常见也最隐蔽的丢失。
3. **锚点缺失或含糊** — `inferred` 不代表可以不标出处；`missing` 节点要写明缺口与补读路径。
4. **母本自我膨胀** — 把案例细节、术语定义全塞进节点；那是 extractor 的职责，母本只记逻辑骨架，细节循锚点回查。
5. **跳过回扫** — 三遍抽完直接定稿，骨架与节点矛盾未被修正。
